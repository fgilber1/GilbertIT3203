HTTP Evolution

HTTP has evolved from the first prototype in 1991, to the current HTTP/2 and HTTP/3 by improving and releasing better versions as the years passed.

Origin

Tim Berners-Lee is credited as the designer of the original HTTP proposal. He designed HTTP with simplicity in mind to help establish his idea of the World Wide Web. In 1991, the first prototype of HTTP was built and had the following functionalities:

  • Client request is a single ASCII character string.
  • Client request is terminated by a single carriage return.
  • Server response is an ASCII character stream.
  • Server response is a hypertext markup language(HTML).
  • Connection is terminated after the document transfer is complete.

HTTP/0.9 Limitations

As HTTP/0.9 was the first version, there were limitations to its functionality:

  • No headers were availabe.
  • No status codes, so errors were not signaled.
  • Only had the GET method.
  • No images, CSS, or scripts.
  • A new TCP connection was needed for every single request.

HTTP/1.0 (1996)

Key changes occurred with the release of HTTP/1.0:

  • Request can consist of multiple newline-separated header fields.
  • The response object is prefixed with a response status line.
  • Response object has its own set of newline-separated header fields.
  • Response ibject is not limited to hypertext.
  • The connection between server and client is closed after every request.

HTTP/1.1 (1997–1999)

Introduced critical performance optimizations that included keepalive connections, chunked encoding transfers, byte-range requests, additional caching mechanisms, transfer encodings, and request pipelining.

HTTP/2 (2015)

How HTTP/2 evolved from HTTP/1.1:

  • It is a binary protocol rather than a text protocol, and allows for the implementation of improved optimization techniques.
  • HTTP/2 is a multiplexed protocol, and parallel requests can be made over the same connection. This removed the constraints of the HTTP/1.0 protocol.
  • It compresses headers since they are often similar among a set of requests. This compression removes the duplication and overhead of data transmitted.

HTTP/3 (2022)

A major change with HTTP/3 is the switch in the transport layer protocol. The predecessors used TCP as their transport layer protocol, but HTTP/3 usess QUIC (Quick UDP Internet Connection). Improvements to speed and reliability result from the change. Other key features of HTTP/3 include:

  • Faster connection setup with QUIC using 0-RTT and 1-RTT handshakes to reduce delay.
  • Built-in encryption.
  • No Head-ofLine blocking at the transport layer.
